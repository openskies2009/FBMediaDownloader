# Facebook Media Downloader

A native macOS application built with **SwiftUI** for downloading available Facebook Page posts and their attached photos or videos to a local folder. It supports multiple managed Pages, date filtering, and custom date-based folder organisation.

> **Project status:** Source-code implementation. Download availability depends on Meta Graph API permissions and the media URLs returned by the API. This repository has not been verified as a fully configured, production-ready Xcode project.

## Features

- **Facebook Page access:** Sign in through the Facebook authorisation flow or paste an access token manually.
- **Managed Page selection:** Load accessible Pages, select individual Pages, or select/deselect all.
- **Date filters:** Choose a start date and an optional end date.
- **Local destination:** Choose a download folder with the macOS folder picker; the app saves a security-scoped bookmark for subsequent access.
- **Folder organisation:** Organise downloads using configurable Page and date components.
- **Post exports:** Save post text as `.txt`, available images as `.jpg`, available video sources as `.mp4`, and `.url` shortcuts pointing back to the original Facebook posts.
- **Progress and status:** Display the current Page and overall Page-level progress.
- **Avoid duplicate filenames:** Skip downloading a media file if a file with the same destination name already exists.

## Requirements

- A Mac with a version of macOS supported by the SwiftUI and AuthenticationServices APIs used here.
- Xcode with Swift support.
- A configured Meta app and a Facebook account authorised to access the intended Pages.
- Appropriate Meta Graph API permissions and access tokens; access is subject to Meta's current review, permission, and API requirements.
- Internet access and sufficient local storage.

The source currently uses **Graph API `v19.0`**. Verify that this API version and its endpoints remain supported before deployment; update the version if necessary.

## Set up in Xcode

1. Create a **macOS App** project in Xcode using **SwiftUI** and Swift.
2. Add `FBMediaDownloaderApp.swift`, `ContentView.swift`, `FBDownloaderEngine.swift`, `FBLoginManager.swift`, and `Models.swift` to the app target. Include `Item.swift` only if needed. Avoid keeping a second `@main` application entry point generated by Xcode.
3. Configure the target's URL Types to register the callback scheme `fb2326255351520305`, as shown in the supplied `Info.plist`. If you use a custom `Info.plist`, ensure the target actually references it or that the equivalent settings are present in Xcode.
4. Review `FBLoginManager.swift` and replace the embedded Meta App ID and redirect URI with values belonging to your own configured Meta application.
5. **Verify the OAuth callback configuration:** The supplied code requests a web HTTPS redirect URI but waits for a callback using a custom `fb...` scheme. A valid, correctly configured callback/redirect mechanism is required; simply registering the URL scheme may not be sufficient. Test and correct this flow before relying on the **Log in with Facebook** button.
6. Configure the required Meta permissions, app settings, and any relevant macOS sandbox/network and user-selected-file access entitlements.
7. Build and run the app.

If the browser-based sign-in flow is not configured, the interface also allows you to enter a valid access token manually.

## How to use

1. Launch **Facebook Media Downloader**.
2. Select **Log in with Facebook**, or paste a valid token into the access-token field and click **Load Pages**.
3. Select the Pages you wish to export.
4. Choose the **Start Date** and, if needed, **End Date**. The **No End Date (Continuous)** option removes the upper date bound; it does **not** implement background monitoring or scheduled recurring downloads.
5. Click **Browse…** to select a destination directory.
6. Optionally enable **Auto-Organize into Date Folders** and select your preferred folder tokens.
7. Click **Start Download** and monitor the status and progress bar.

## Folder patterns

The default organisation pattern is:

```text
PAGE_NAME / YYYY / MONTH
```

Supported tokens:

| Token | Meaning | Example |
| --- | --- | --- |
| `PAGE_NAME` | Facebook Page name | `Example Page` |
| `YYYY` | Four-digit year | `2026` |
| `YY` | Two-digit year | `26` |
| `QUARTER` | Calendar quarter | `Q4` |
| `MONTH` | Full month name | `November` |
| `MM` | Two-digit month | `11` |
| `DD` | Two-digit day of month | `04` |

With automatic organisation disabled, the engine saves files inside a folder named for the Page.

Example output:

```text
Downloads/
└── Example Page/
    └── 2026/
        └── November/
            ├── 123456789_987654321.txt
            ├── 123456789_987654321_0.jpg
            ├── 123456789_987654321_0.url
            └── 123456789_987654321_1.mp4
```

Names above are illustrative. Actual filenames are based on Graph API post IDs and attachment indices. Text files are written only when a post has message text. Shortcut files are created for successfully downloaded media.

## How downloading works

The engine calls `GET /me/accounts` to discover accessible Pages and their Page tokens. For each selected Page it requests paginated posts from `/{page-id}/posts`, including message, creation time, and attachment information. It attempts to obtain full-resolution images using the attachment target's `images` field, falling back to the attachment image URL when necessary. Video files are saved only when an attachment exposes a usable `media.source` URL.

Post text is saved in UTF-8. The code also attempts to set local file creation and modification dates to the original post date. Existing destination media files are skipped rather than overwritten.

## Important limitations

- **Not a general Facebook downloader:** The implementation is designed around Pages returned by the authorised account's `/me/accounts` endpoint. It does not provide arbitrary profile, group, or URL downloads.
- **Not all videos or images are accessible:** Graph API permissions, media types, privacy restrictions, and missing source URLs can prevent downloads. Some attachments may yield previews rather than original media.
- **No automatic sync:** A download is started manually. Removing the end-date limit does not cause the app to watch for future posts.
- **Progress is per Page:** The progress bar is not a precise per-file transfer indicator.
- **Error reporting is limited:** Several network and file-write failures are silently skipped in the current engine; the final “Download Complete!” message does not guarantee that every attachment succeeded.
- **No comprehensive duplicate detection:** The app checks existing destination filenames, not media hashes or cross-post duplicates.
- **Date parsing should be validated:** If a post's timestamp cannot be parsed, the current code falls back to the current date.

## Security and privacy

**Important:** The current implementation saves the Facebook access token using `@AppStorage`, which is backed by app preferences rather than the macOS Keychain. For production use, migrate credentials to Keychain storage. Avoid committing tokens, downloaded private content, or configuration secrets to source control.

The Graph API requests currently include access tokens in query strings. Consider a safer authenticated-request design and ensure tokens are not exposed in logs or diagnostics. Download and retain only content you are authorised to access, and comply with Meta's platform terms and applicable privacy and copyright requirements.

## Troubleshooting

| Problem | Things to check |
| --- | --- |
| Login fails or never returns to the app | Meta App ID, redirect URI, custom URL scheme, app settings, and OAuth callback handling. |
| No Pages appear | Token validity, Page roles/access, permissions, app review, and Graph API response errors. |
| API requests fail | Token expiry, permission changes, rate limits, and whether Graph API `v19.0` is still available. |
| Some media is missing | Whether the Graph API response actually contains an accessible image or video URL. |
| Nothing is written to disk | Destination selection, sandbox entitlements, security-scoped bookmark validity, and filesystem permissions. |
| Downloads stop partway through | Network timeouts, expired media URLs, API errors, and the current engine's limited error handling. |

## Suggested future improvements

- Keychain-backed token storage and robust OAuth callback handling.
- Detailed transfer logs, per-file progress, cancellation, and retry controls.
- Incremental sync, resumable downloads, and optional scheduling.
- Safer filename sanitisation and more comprehensive duplicate detection.
- Automated tests for API decoding, date parsing, and folder paths.
